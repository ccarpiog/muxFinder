## Spike answers (local and Saturno)

- **(a) Bury.** SetProperty `buried=true` answers `OK` in 0–20 ms, and the launch tab is in
  `buried_sessions` within about 55 ms. Its window closes and the tmux tabs stay. The buried tab
  still owns its connection, so the bound detach works. A second bury answers `OK`.
  `GetProperty` `buried` answers `1`/`0`. Restoring opens a new window. S1–S3 and S8 confirmed.
- **(b) Without `Disinter`.** A buried tab whose helper exits stays as a dead buried session
  (S4).
- **(c) With the helper.** The helper's restore brings back a tab buried during its hold, and
  nothing is left behind. No sample sent after a DSR answer still showed the tab buried,
  consistent with S7.
- **(d) Close.** A forced `Close` of a buried session, dead or live, answers `OK`, and the
  session is gone within about 18 ms.
- **(e) Abnormal end.** After a SIGKILL of the attach child, iTerm2's parser stays in tmux mode
  and the first restore is lost. Fix: a line feed first, then a second restore when the first
  is unanswered. With it, the tab is back about 2.1 s after the kill and the explanation is
  drawn (inferred from the answered DSR). Return was not tested, because synthesized keystrokes
  are forbidden. The `muxfinder-test-*` session survives locally and on Saturno.
- **Persistence (design item 5).** The helper alone recovered every abnormal end tried, so D29
  keeps the coordinator's list of buried launch tabs **in memory only**.

## Deviation: iTerm2's auto-hide setting is on here

This Mac's iTerm2 has `AutoHideTmuxClientSession` (*Automatically bury the tmux client session
after connecting*) **on**; the spike only read it. So no run used default preferences. iTerm2
buried each launch tab itself (S6) and restored it when tmux ended (S5's "on" branch). The
harness reproduces the default by burying the tab again at the moment the default would leave
it buried. S5's "off" branch rests on reading iTerm2's source only. The user's report on
2026-10-24 (the launch tab stays visible) suggests the setting was switched on after that
report. This affects 13c's acceptance wording ("with default iTerm2 preferences"). See the
checkpoint's *Open risks*.

## Review

Codex (`autoclaude-review.sh`, 20 min budget): **ship-with-fixes**, 0 blockers, 1 should-fix,
in `docs/reviews/phase-13a.md` (brief `docs/reviews/phase-13a.brief.md`).

- **Should-fix** (`TerminalStatusRequest.swift:109`): the restore exchange could block
  indefinitely despite its 2 s bound. After SIGINT/SIGTERM ended `waitForReturn()`, its reader
  stayed alive and could take the reply between `poll()` and `read()`, and a blocking write
  could also stall.
  - **Fix** (review-fix worker): one absolute deadline bounds every `poll()`, for the writes and
    the read alike. All I/O goes through non-blocking descriptors opened afresh on the terminal
    (`NonBlockingTerminal.swift`); only if that open fails is `O_NONBLOCK` set on the shared
    descriptor, and it is put back on every path. `waitForReturn()` now uses
    `TerminalReturnReader`, which reads only after `poll()` and also watches a wake pipe, and
    the wait returns only once that reader has returned.
  - **Regressions:** a back-pressure test, and a PTY binary test where a signal ends the Return
    wait while the final answer is typed one byte at a time. Both fail against the old code:
    the blocking write overran its bound, and under SIGINT the helper never exited.
  - The reviewer's NOT-VERIFIED note (coverage for this race and for back pressure) is answered
    by these two tests.
- A kill by SIGHUP or SIGKILL in the middle of the exchange cannot restore raw mode; the tab
  ends with the helper anyway.
