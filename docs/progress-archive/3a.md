## What was built

- `Sources/MuxFinderCore/ITerm2/`:
  - `ProtoWire`, `ProtoReader`, `ProtoWriter` — hand-written proto2 wire codec: varint (incl.
    negative int32 as 10-byte varint), bool, enum, length-delimited, skipping of unknown fields
    of all four wire types. Malformed input (truncated/overlong varint, length past end, field
    number 0, wire types 3/4/6/7, nesting over 100 levels) → typed `ProtoWireError`.
  - Typed messages: `ITerm2Envelope` (client and server envelopes), `ITerm2ListSessions`
    (windows → tabs → split tree → sessions; tmux window/connection ids live on tabs only),
    `ITerm2CreateTab` (custom profile properties; helper builds the command properties the
    Python module sends for `Window.async_create(command=…)`), `ITerm2Tmux` (ListConnections,
    SendCommand), `ITerm2Activate`, `ITerm2ListProfiles` (helpers for `Name`/`Guid`),
    `ITerm2JSON` (JSON string encoding matching Python `json.dumps`). Unknown enum values
    decode to `unknown(Int)`.
- `scripts/dev/gen-iterm2-fixtures.py` — dev-only, run with iTerm2's interpreter and `-I`.
  Request fixtures come from the Python module's own `iterm2.rpc` functions run against a
  stand-in connection (exact `SerializeToString` output); response fixtures are built with
  `api_pb2`, some carrying unmodeled and unknown fields; merge/oneof fixtures are checked
  against what `api_pb2` decodes before being written. 31 synthetic `.bin` fixtures in
  `Tests/MuxFinderCoreTests/Fixtures/iterm2/`.
- Tests: `ProtoWireTests`, `ITerm2GoldenTests` (byte-for-byte request encodings, response
  decodes, codec edge cases, malformed input, merge and oneof regressions).
- `PLAN.md` *Verified facts*: field numbers for the modeled messages and the CreateTab property
  keys/encodings. `docs/TESTING.md` and `CLAUDE.md`: fixture regeneration command.

## Decisions

- Decoder leniency: invalid UTF-8 in strings becomes U+FFFD; a known field arriving with an
  unexpected wire type is skipped (protobuf's own rule).
- Server envelope: only real members of the `submessage` oneof (2, 100–133, 1000, from
  `api_pb2`) switch the response; the last member present wins; unmodeled members →
  `.unsupported`; field numbers outside the proto are skipped.
- proto2 merge semantics for singular embedded messages (envelope, split tree, split-tree links,
  tmux payload): pieces are read in turn by one reader that refuses a value spanning two pieces
  (Python's `api_pb2` rejects that input too), so no copy and the input size bounds the total.
- A oneof member superseded by a later different member is skipped without decoding, so
  corruption inside it is not reported (more lenient than Python).
- Python module quirks found: `rpc.async_create_tab(command=…)` raises TypeError in module 2.11
  (fixtures use `Window.async_create(command=…)`); the module's Activate sends
  `ignoring_other_apps=true` whenever app options are given (the app-only fixture sets both
  options true, so our encoder matches). `CreateTabResponse.tab_id` is numeric while ListSessions
  tab ids are strings.

## Review findings and resolutions

1. Should-fix — unknown fields ≥100 replaced a decoded response (`ITerm2Envelope.swift`). Fixed:
   only real oneof members switch it; regression fixtures for unknown fields before/after and
   unmodeled-then-modeled / modeled-then-unmodeled orders.
2. Should-fix — repeated occurrences of an embedded message erased earlier content. Fixed with
   proto2 merging throughout; the reviewed bytes `08 01 92 07 02 08 01 92 07 00` and nested
   split cases are reference-backed fixtures.
