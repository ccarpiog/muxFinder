# Phase 7b — refresh engine (archived narrative)

Risk `high`; workers: opus implementation + opus fix worker; orchestrator rewrote one
pre-existing load-sensitive test. Design: `PLAN.md` **D20**.

## What was built

- `Sources/MuxFinderCore/Refresh/RefreshCoordinator.swift` — an actor over a `HostList`'s
  enabled hosts. At most 3 probes at once (first come, first served); one probe per host, a
  retired probe (from an edited or removed host) included, which keeps its slot until its task
  ends, while hosts queued behind a blocked one go ahead. A request while a host's attempt runs
  marks one follow-up attempt (joining was rejected: every request gets a result that started
  after it). Results are dropped by per-host generation, configuration revision and cancelled
  attempts. Cadence: immediate on popover open, 15 s while visible, 5 min in the background;
  background-only backoff 30 s, 1 m, 2 m, 5 m, 15 m (cap), reset by a success, bypassed by
  manual retry and ignored by the visible cadence. Sleep and `stop()` cancel in-flight probes
  (process groups killed by the Phase 1 runner) and start a new work epoch that suspended
  `refreshOnce` rounds check before each host request and before the attachment check; wake
  refreshes after 5 s; a network path change refreshes the failing hosts. Seams:
  `HostDiscovering`, `AttachClock`, `AttachmentIndexing`. Phase 8 reads `updates()`, an
  `AsyncStream<RefreshState>`.
- `Refresh/HostSnapshot.swift` — per host: live or stale, `lastAttempt`, `lastSuccess`,
  classified outcome, failure count, node name, sessions keyed by host id plus server identity.
  After a failure that follows a success the sessions stay, marked stale. Attachment check
  results (D16) merge into the sessions, with D16's failure policy; attachment checks run only
  while the popover is visible.
- `Refresh/RefreshSystemEvents.swift` — a small adapter over `NSWorkspace` sleep/wake
  notifications and `NWPathMonitor` for Phase 8; start and stop are serialized by a generation
  under a lock, and only the current generation's observers forward events.
- `Sources/muxfinder-probe/RefreshCommand.swift` — `refresh --once [--config <hosts.json>]
  [--attachments]`; the default never contacts iTerm2 (`attachments.state` `notChecked`).
- Tests: `RefreshCoordinatorTests`, `RefreshScheduleTests`, `RefreshSnapshotTests`,
  `RefreshTestSupport` (fake prober, fake clock); `DiscoveryTestSupport` gained a fake-tmux
  `hang-pids` mode for the real-process-runner stop test.
- `ProcessRunnerTests.doesNotBlockTheMainActor` (orchestrator): the fixed-window tick count
  (failed 2 of 12 runs at load average ~17) became a handshake — the child waits for a file a
  main-actor task creates only after the child has started, so a blocked main actor would end
  the run by its timeout.

## Review

Codex → `ship-with-fixes`, 0 blockers, 3 should-fix, `docs/reviews/phase-7b.md`:

1. Sleep interrupting `refreshOnce(includeAttachments: true)` let the suspended round go on to
   submit the attachment check → work epoch checked after every suspension.
2. `setHosts` replaced an edited host's entry while its retired probe still ran, so a second
   probe for the same host could start → retired probes count in the per-host guard; the
   waiting host starts when the retired one ends. Two earlier tests that assumed the old overlap
   were rewritten to the new rule with the same discard checks.
3. `RefreshSystemEvents.start` published its continuation before installing observers, so a
   concurrent `stop` could leave observers installed → generation under a lock; a start that
   lost the race removes what it installed. Sibling: stale path updates from a losing start are
   filtered by generation too.

Each regression failed on the old code (worker-confirmed) and passes now.

## Open risks

- `refresh --once --attachments` was not run for real (it would query the user's iTerm2 tmux
  connections); the merge is covered hermetically only.
- Real sessions through the engine were seen only locally (a private server); Saturno had no
  server, so remote session parsing through the engine relies on Phase 2's discovery tests.
- Two concurrent `RefreshSystemEvents.stop()` calls: the second may return before the first has
  finished tearing down (harmless for Phase 8's single owner; noted by the fix worker).
- A rename or profile change of a host does not invalidate in-flight work; only mode,
  destination or tmux override count as an edit (D20).
- `keepsTrailingSemicolonsOnAPrivateServer` (6a) failed about 1 in 20 runs under heavy load in
  the worker's measurements; not seen in the orchestrator's 14 runs.
- `/private/tmp/mfx-fix.*` folders from 2026-10-21 (an earlier phase's fixture work) remain;
  they do not match the `^mfx\.` leftover pattern and were left alone.
