## Decisions

- Orchestrator, before the worker (recorded in `PLAN.md` "### Phase I-7"): the `~` rule (field
  matched as typed; on This Mac each entry matched as stored, with a leading home folder written
  `~`, and with a leading `~`/`~/` spelled out; SSH hosts as stored; `~user` never expanded) and
  the clearing rule (empty trimmed text never opens, closes a typing-opened list, keeps a
  button-opened one).
- Worker: the "opened by" state is `DirectoryPickerState.opening` (`request` for the button,
  Space and ⌥↓; `typing`), `isOpen` derived. A user edit reaches `directoryFieldEdited(from:)`;
  a pick fills through `fillDirectoryField(_:)`, which is no edit. The home folder is injected
  (`thisMacHome` from `AppEnvironment.homeDirectory`: `NSHomeDirectory()` in the app, `nil` in
  tests and self-tests, `/Users/example` in fixtures). The announcement goes through
  `AppEnvironment.announce` → `AppModel.announce` (an `NSAccessibility`
  `announcementRequested` at medium priority; tests record it), spoken only when an edit opens
  the list, changes its rows or closes a typing-opened list for lack of matches; the list's
  accessibility value carries the same summary; the field's hint says typing filters the list.

## Open risks / deviations

- A list opened with the button while the field holds text (e.g. right after a pick) shows only
  the matching entries, as the specification's pure rule says; the existing "directory saved
  already" gallery state now shows its one matching row.
- "Sessions on <host>" is capped at 10 folders before filtering, so typing cannot find an
  eleventh session folder.
- VoiceOver says nothing on a host change; it was never turned on in a check. Real typing, keys
  and VoiceOver in both panels are checklist 21's.
