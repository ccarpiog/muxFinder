## What was built

- `TerminalDefinition`, `TerminalDefinitionParser` (strict schema 1, plain-sentence
  problems), `TerminalDefinitionProblem`, `TerminalDefinitionLoader` (read-only; the user
  folder reached from `/` with no symbolic link on the way, 0700, no ACL, files regular,
  owned, not group/world-writable, read through the open descriptor, 64 KiB definitions,
  256 KiB scripts, 32 files; overrides by id, duplicate user ids both refused; an unsafe
  folder gives one problem), `TerminalLaunchCommand` (`shellText` through
  `TerminalCommandText`, `words` limited to D2's characters plus `/ . _ + -`, `exec` argv
  expansion), `AppleScriptRunner` (`NSAppleScriptRunner` on the main actor, one
  `kASSubroutineEvent` per call, strict replies, typed failures with the OSA error number;
  `FakeAppleScriptRunner`), `TerminalScriptCalls` (the three handlers' reply checks),
  `TerminalAppFacts` (LaunchServices path and version, minimum version, running, permission
  through `AutomationPermission`, `exec` "not needed"; a fake-able inspector).
- Built-ins `Resources/Terminals/{terminal,ghostty}.{json,applescript}`: Terminal `do script`
  with no `in`, returns window id and tab `tty`, focus by `tty`, close by id only when no tab
  is `busy` (error 1001), -1728 when gone; Ghostty `new surface configuration` + `new window
  with configuration`, focus and close by window id.
- `terminals list`: the three app rows unchanged, plus `definitions` and `problems`,
  `--builtin-directory`, `--user-directory`; the permission read moved into the core with
  the same behavior.
- Worker additions beyond the calls: no ACL on the folder and its files; script names end in
  `.applescript`; each `exec` placeholder at most once; a probe fix (`standardizedFileURL`
  turned `/private/tmp` into the `/tmp` link). Check folders must come from `mktemp -d
  /private/tmp/mfx.XXXXXX` (`CLAUDE.md`).

## Review

Codex (`autoclaude-review.sh`, 15 min) → `ship-with-fixes`, 0 blockers, 1 should-fix:
duplicate JSON member names passed the strict schema (`JSONSerialization` keeps one).
**Fixed** by a review-fix worker: `JSONDuplicateNameScanner` walks the bytes after
`JSONSerialization` accepts them and refuses any object with a repeated name at any level
(names compared after decoding escapes and surrogate pairs; canonically equivalent names count
too), `.duplicateKey` "This file has the key open.kind more than once."; UTF-8 only (a UTF-16
file is `.notJSON`), nesting capped at 64. Six regression tests from raw JSON text; with the
scan removed five fail (33 issues), the array-repeat test passes either way as intended.
`docs/reviews/phase-I-12b1.md`.
