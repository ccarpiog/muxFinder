# Phase 6a — new session and vanished sessions (archived narrative)

Risk `high`; workers: opus implementation + opus fix worker. Phase 6 was split into 6a and 6b
(Move here) in `PLAN.md` before the first worker. The phase's code, review and fixes were
committed in `0210999`; its last acceptance item, a final-tree `e2e-remote saturno-m4` run,
waited for iTerm2's thread count to fall (Phase 7a ran meanwhile) and passed on top of
`228f8da`.

## Acceptance (all met)

- Hermetic tests for the create argv and D3 string (hostile names and directories, `~/`, `#`
  doubling, trailing `;` as `\;`), `-P -F` parsing, collision via `has-session` and the
  duplicate-session error, invalid names with zero processes run, ssh auth failure ("Set up SSH
  in iTerm2 first") vs. `connectionLost` (may have created, refresh-triggering),
  `createAndAttach`, `triggersRefresh`.
- Real `e2e-local` 15/15 on the final tree (vanished session `sessionGone` with the count
  unchanged, collision with the session unchanged, invalid names, missing Unicode directory, new
  session in a directory with spaces, Unicode, `#` and a trailing `;`).
- Real `e2e-remote saturno-m4` 16/16 twice before the review fixes, and **16/16 on the final
  tree** (104.4 s, 2026-10-22): vanished session, collision, invalid names, missing Unicode
  directory under `~/`, new session with a trailing `;` in `~/Library/Application Support`.
- D18, `docs/TESTING.md`, `CLAUDE.md` updated.

## Decisions

New **D18** (`TmuxCommands`: one static script, local argv or ssh with BatchMode;
`has-session '=name'` then `new-session -d -P -F`; `~/` resolved on the host; missing directory
refused; `#` doubled and a trailing `;` written `\;` for tmux's parsers; strict
`CreatedSession` parsing with `attachTarget(on:)`; ssh 255 is "nothing created" only for
pre-connection stderr classes, otherwise `connectionLost`; `createAndAttach` skips the
existing-attachment check, so it never queries the user's connections; `triggersRefresh` on the
failure and result types). The probe is `new-session --local | --ssh <dest> --name …
[--dir …]` (the plan's `--host` shape changed for consistency). Names containing `\` are
refused (tmux stores them doubled). The e2e harness kills a test session only through one
`if-shell -F` command that checks id, created time, pid, start time, socket path and exact name
in the same server connection. On Saturno the directory check uses an existing directory with a
space and a missing Unicode one (no remote file writes).

## Review

Codex → `ship-with-fixes` (`docs/reviews/phase-6a.md`), 1 blocker (the harness's identity
check and kill were separate tmux calls, so a restarted server reusing `$N` could lose a user
session), 2 should-fix (a trailing `;` is a tmux command separator even in argv; ssh exit 255
after a successful create reported as "nothing created"). A fix worker fixed all three: one
`if-shell -F` check-and-kill, `\;` escaping in the static script, a `connectionLost` class.
Regressions fail on the old code; private tmux server checks reproduced the `$0` reuse race and
the `work;` mis-parse. Re-verified hermetically, with a real final-tree `e2e-local`, and later
with the final-tree `e2e-remote`.

## Open risks / deviations

- iTerm2 thread ratchet: each real e2e run adds about 12 iTerm2 threads (GCD workers stuck in
  `-[NSAnimation _runBlocking]`, the 5b stall pattern at 64). During 6a the count went 16 → 23
  → 35 and sat at 34–35 for over an hour; it was back to 15 about two hours later with no
  restart. The final-tree `e2e-remote` took it from 16 to 26.
- A name starting with `$`, or one naming a client's terminal, can be refused as existing (tmux
  resolves those targets as an id or a client); a real collision is never missed. A name
  containing `#[` is stored by tmux as `##[`.
- `NewSessionRequest.command` exists for harnesses only (unvalidated; its first word must not
  start with `-`). The probe `new-session` was not run for real (its pane would start the
  user's login shell); its path is the one the e2e steps exercise.
- "Timeout, server … not responding" counts as unreachable for discovery but as
  `connectionLost` (may have created) for creation, because it appears only once connected.
