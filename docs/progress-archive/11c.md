# Phase 11c — Settings section and launch-time rewrite

- **Risk class:** routine. **Worker model:** opus (implementation worker, then a review-fix
  worker). Orchestrator: verification and checkpoint only.
- **Scope:** the Settings controls over Phase 11a's per-host persistent-profile fields, a
  "Persistent profiles" Settings tab with Install / Remove, the copy, keeping an installed
  `DynamicProfiles/muxFinder.json` current (at normal-mode launch and after a Settings save),
  preview fixtures and screenshots. Hermetic: no iTerm2 contact, no real `DynamicProfiles/`
  write, no real `hosts.json` read or write.

## Decisions (recorded in PLAN.md D26)

- The section is its own Settings tab, between Hosts and General.
- "Installed" is the user's sticky choice: the app writes `muxFinder.json` only when the user
  presses "Install profiles" or when muxFinder's own generated file is already there. Install
  always uses the **saved** host list; with unsaved edits it stays enabled and shows a note.
- A Settings save while the file is installed updates it at once; turning off the last
  profile removes it (empty document → removal of a generated file only).
- At launch, only in normal mode and only with a `saved` host list, an out-of-date generated
  file is rewritten; nothing else is written; only error kinds are logged (no user data).
- Ownership: new `PersistentProfiles.isGenerated(_:)` (one `Profiles` key, a non-empty array,
  every entry with a generated GUID and the `muxFinder` tag); a `muxFinder.json` that fails it
  is the user's: status `notMuxFinders`, error `fileNotMuxFinders`, never replaced or removed
  by the app. Policies: `replaceGenerated` for the "Install profiles" button,
  `updateExistingGenerated` (review fix) for every automatic update — under the lock it
  creates nothing (no folder or file → outcome `notInstalled`), refuses a user's file, and an
  empty document removes only a generated file; `remove(onlyIfGenerated:)` for "Remove
  profiles". 11a's `createOnly` / `replaceExisting` / `remove(expecting:)` are unchanged (the
  e2e harness keeps `createOnly`).
- Each operation (Install, Remove, Check again, the after-save update) takes its host list
  when it starts and never re-reads the model after an `await` (review fix); Check again does
  nothing while the host list is loading.
- The second-tab open item is settled with copy only (iTerm2 not run).

## Review

- Codex → `ship-with-fixes`, 1 blocker, 1 should-fix; `docs/reviews/phase-11c.md`, brief
  `docs/reviews/phase-11c.brief.md`.
  - **Blocker** (`SettingsModelProfiles.swift`): the after-save update re-read
    `model.profileHosts` after awaiting the status, so closing and reopening Settings (reload →
    `.loading` → empty list) could install an empty document and delete the user's installed
    profiles. Fixed: the update carries the saved `HostList`; Install / Remove / Check again
    capture theirs at the press. Regressions `reloadDuringASaveUpdateKeepsTheSavedList`,
    `operationsKeepTheirHostList` (each failed with the fix reverted).
  - **Should-fix**: automatic updates checked status separately from installing, so a file
    removed in between (another muxFinder process, the user) was created again. Fixed with
    `ReplacePolicy.updateExistingGenerated` and the seam's `update(_:)`. Regressions
    `automaticUpdatesNeverRecreateARemovedFile`, `updateExistingGeneratedNeverCreatesTheFile`,
    `realSeamOverAPrivateFolder` (each failed with the fix reverted).

## Open risks / deviations

- A file removed by something outside muxFinder in the instant after the locked check makes an
  automatic update report `fileChanged` (a failure line) rather than `notInstalled`; nothing is
  created either way.
- Owed to the user (listed in `docs/TESTING.md`, Phase 11c): a real Install / Remove from an
  installed bundle, making a profile iTerm2's default, a second tab of the same profile, and a
  launch after moving the app (the rewrite for real).
- `--report-menu-bar-item` was re-run by the implementation worker (no `hosts.json`: no child,
  nothing written) before the review fixes; the fixes touch only the update paths that need a
  saved host list.
