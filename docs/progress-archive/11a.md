# Phase 11a — Profile core, helper mode and probe

Closed 2026-10-23. Risk class: high. Worker model: opus (implementation worker, then a review
fix worker); the orchestrator made one small follow-up fix inline (below).

## Scope

Phase 11 ("Persistent Work profiles") was split before the first worker into 11a (this phase,
hermetic), 11b (real profile runs) and 11c (Settings section and launch-time rewrite); the split
is recorded in `PLAN.md` "### Phase 11". 11a delivers the host-list fields, the pure profile
generator, the atomic installer/remover, helper mode `muxfinder-launch profile <host id>`, and
the probe commands 11b needs. Design: **D26** in `PLAN.md` (D8, D11, D14, D19 edited).

## Acceptance

- Host-list fields (`persistentProfileEnabled`, default session name, default `main`, per-host
  parent profile name): old `hosts.json` files load and save back byte for byte — met
  (`HostProfileFieldsTests`, `HostEditorTests`).
- Generator golden tests for local and SSH hosts, with and without a parent; helper paths with
  spaces or special characters refused — met (`PersistentProfilesTests`, fixtures in
  `Tests/MuxFinderCoreTests/Fixtures/profiles/`).
- Installer: atomic write, identical content not rewritten, stale detection, only
  `muxFinder.json` written or removed, symlink refusal, sibling hashes unchanged; no opted-in
  host removes the file — met (`PersistentProfileInstallerTests`).
- Helper profile mode: nesting guard on `TMUX` / `MUXFINDER_LAUNCHED` (non-empty) execs the
  login shell (passwd entry, else `/bin/zsh`, then `/bin/sh`); unknown or not-opted-in host and
  every failure fall back to the login shell; local argv and remote D3 script; every helper mode
  sets `MUXFINDER_LAUNCHED=1` for its children — met (`ProfileLaunchTests`,
  `LaunchHelperProfileTests`, `LaunchHelperProfileBinaryTests`).
- Probe `profiles show`, `profiles hashes` (read-only `defaults export`), `e2e-profile --local |
  --ssh` implemented and tested with fakes (`ITerm2ProfileSnapshotTests`,
  `PersistentProfileRunTests`); `iterm2 list-profiles` already printed GUIDs, unchanged — met.
- Nothing contacted the real iTerm2; the real `DynamicProfiles/` folder stayed empty and the
  support folder held only `launch/` after every run — met (orchestrator `ls -A`).

## Decisions

- D26 (see `PLAN.md`): schema stays 1 with optional fields; the parent profile is per host;
  default session names may not start with tmux target-syntax characters (`$ = @ % ! ~ { + ^`,
  checked on the first Unicode scalar) because `-A` attaches through a target lookup; the e2e
  test host list is honored only in test mode and only for its own host id, so the production
  command stays exactly `<helper> profile <id>`; `e2e-profile` creates `muxfinder-test-profile`
  itself (panes run `sleep 600`) so `-A` attaches and no login shell starts inside tmux.
- Review fix: installs and removals in every muxFinder process hold an exclusive `flock` on
  `~/Library/Application Support/muxFinder/profiles.lock` (5 s wait, errors `busy` /
  `lockUnavailable`), never a file in iTerm2's folder; a rollback deletes the displaced entry
  only when its device and inode match this install's own temporary file, else keeps it
  (`displacedEntryKept`).
- Review fix: `e2e-profile` cleanup lists the tab's own connections (late ones included) and
  detaches each through its binding; only a listing without the connection counts as detached;
  the tab is force-closed only when a listing just before shows it owns no connection; otherwise
  the tab stays, the session is not killed, and the step fails printing the manual `detach` and
  kill commands.
- Orchestrator follow-up (the fix worker's open question): `Validation.sessionName`'s `:`, `.`,
  `\` and leading `-` checks and `sshDestination`'s leading `-` check now run on Unicode scalars,
  not `Character`s, so a combining mark after the reserved byte no longer hides it. Five
  regression cases in `ValidationTests` failed on the old code and pass with the fix.

## Open risks (carried to the live checkpoint)

- Owed to 11b: iTerm2 loading and dropping the file (`ListProfiles`), skipping the hidden temp
  file, the 3-argument split of the profile command, close-on-end, unchanged hashes, no "Dynamic
  Profiles Error" alert, the unknown-parent fallback, confirmed control-mode connections locally
  and on Saturno. Planned steps in `docs/TESTING.md`.
- The `-A` target-syntax restriction comes from tmux's target syntax and was not tried on a
  server; the "create" branch of `-A` is covered by tests only.
- A login shell that exits by itself within 3 s of starting is beyond the helper's 10 s hold.
- For 11c: unknown what iTerm2 does when a second tab of the same profile attaches the same
  session; dynamic profiles without a parent inherit from the default profile, so if a
  persistent profile becomes the default, the user's other parentless dynamic profiles without
  their own `Custom Command` would run the helper — the Settings copy must warn, or the
  generator must set a parent.
- `profiles show --config` takes the `hosts.json` file path (like `hosts show`), not a folder.

## Review

Codex → `ship-with-fixes`, 1 blocker, 2 should-fix (`docs/reviews/phase-11a.md`, brief
`docs/reviews/phase-11a.brief.md`):

1. BLOCKER — installer rollback could delete a newer concurrent update → cross-process `flock`
   plus an identity check before deleting a displaced entry.
2. SHOULD-FIX — `e2e-profile` cleanup could force-close a tab still holding a gateway →
   reconcile and detach through bindings; never close a tab that may hold one.
3. SHOULD-FIX — combining marks bypassed the leading target-character guard → first Unicode
   scalar check.

All fixed by a fix worker; each regression failed with its fix reverted (45 validation cases,
the swap-back and lock tests, both cleanup tests) and passes with it.
