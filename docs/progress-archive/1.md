## What was built

- `Package.swift` (tools 6.0, macOS 14, Swift 6 mode): library `MuxFinderCore`, executables
  `muxfinder-launch`, `muxfinder-probe` (placeholders) and `MuxFinderApp` (minimal
  `MenuBarExtra`), test target `MuxFinderCoreTests` (Swift Testing).
- `Sources/MuxFinderCore/Process/`: `ProcessRunner` protocol, `ProcessEnvironment` (Homebrew
  PATH helper), `PosixSpawnProcessRunner`, `ProcessSupervisor` + `ProcessSupervisorIO`
  (blocking work on a dedicated thread; `POSIX_SPAWN_SETPGROUP`; stdout/stderr drained
  concurrently, capped at 1 MiB each; timeout and cancellation send SIGTERM to the group, then
  SIGKILL at the 2 s escalation deadline).
- `Sources/MuxFinderCore/Shell/`: `ShellQuoting` (`posixSingleQuote`,
  `remoteCommand(script:args:)`; scripts are a `StaticShellScript` type buildable only from
  string literals), `Validation` (typed errors, English messages).
- `Sources/MuxFinderCore/Config/AppPaths.swift` (0700 dirs, test override),
  `Sources/MuxFinderCore/Diagnostics/DiagnosticsLog.swift` (actor ring buffer + `os.Logger`
  subsystem `cc.carpio.muxfinder`; flattens line breaks, caps detail length).
- `.swift-format` sets only `spacesBeforeEndOfLineComments: 1` so `} // End of …` comments in
  the `CLAUDE.md` style lint clean.

## Decisions and deviations

- Cancellation throws `CancellationError` rather than returning a result.
- A process that exits normally gets no signal, so background processes it started (e.g. an ssh
  ControlPersist master) keep running; the runner waits at most 500 ms for pipes such leftovers
  hold.
- Processes that leave the group on purpose (`setsid`) can't be reached; documented in code.
- Stdin can also be fed data (beyond `/dev/null` default).
- **Review fix (should-fix, `ProcessSupervisor.swift`):** after SIGTERM the supervisor now honours
  the full escalation deadline before SIGKILLing survivors, independent of output draining, and
  ends early once the group is empty. The leader stays unreaped (zombie) until signalling is
  done so its pgid can't be recycled. Measured on macOS 27.2: `kill(-pgid, 0)` with only a
  zombie leader left returns **EPERM**, not ESRCH, so "no live member" = ESRCH or EPERM.
  Cancellation gets the same grace period, then skips the output drain. Three regression tests
  added (cleanup after timeout, after cancellation, TERM-ignoring descendant killed at the
  deadline); they failed against the old code.
- Test helper `runArmedTimeoutScenario`: the script writes an `armed` file once setup is done;
  an un-armed run is retried with double the timeout. Added because under very high load (load
  average 80–200 during the fix) shells started too slowly and timeouts fired before setup.
