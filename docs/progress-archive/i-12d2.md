  follow the terminal of the backend that ran the action, menus and panels the applied choice;
  a window error is worded by its own app name.

  ("Show window", "Open System Settings…"); `SessionActivity.isAttached` closes the switcher.

  "Try again" (as iTerm2's); a confirmed window whose one focus failed keeps "Confirmed…" with
  a note.

  owed); -600, -609 and -10810 read "isn't running and couldn't be opened".

  of an attachment muxFinder made there; none exists without such a record). A new
  `ActionKind.detachOpenedIn` makes "Try again" repeat it on the same backend.
- A refused plain detach (`notSent`) also forgets the model's record (the backend dropped it).
- Beyond the block, the host problems' "Set up SSH … first", Settings' "Test connection" and
  "Detect" lines, New session's "Creating …", the two panels and Quit's help follow the choice
  (iTerm2's unchanged).
- Fixtures choose a terminal through definitions decoded in memory from copies of the
  built-ins' JSON: the core's `LoadedTerminalDefinition` and `TerminalDefinitionCatalog` got

## Review fixes

The Codex review (`docs/reviews/phase-I-12d2.md`) found three should-fix problems; each is fixed
with a regression in the new `Tests/MuxFinderUITests/TerminalReviewFixTests.swift` (7 tests in
1 suite, over the I-12c3a seam harness with a stand-in backend), and every one of them fails
with its fix reverted (the five written first also failed on the code before the fixes). No
core change; PLAN.md D25 and D38 *The UI (I-12d2)* say what changed.

- **Stale window records dimmed Move here** (introduced by this phase, not inherited:
  `SessionRow.offersMoveHere` gained `&& !hasWindowHere` here). The model's copy of a plain
  backend's window record is never checked again by a refresh, so after the client was detached
  in tmux or the window closed, "Move here…" stayed dimmed for good. It is now dimmed only by
  D16's index, as before this phase; the plain backend already checks its own record at a move
  (helper result, then the bound presence check): it refuses a live one
  (`alreadyOpenInTerminal`, "This session is already open in a … window" with "Bring forward"
  and "Detach from this Mac") and drops a stale one and moves here. iTerm2 unchanged (its rows
  never have a window record). Regressions `aCachedWindowRecordNeverDimsMoveHere`,
  `theMenusOfferMoveHereBesideAWindow`; the attach screenshots were rendered again (Terminal's
  context menu card).
- **A detach's "Try again" vanished after a change of terminal.** `detach(_:openedIn:)` only
  ran for a terminal that was not the chosen one, so when a terminal change that waited for the
  detach made its terminal the chosen one, "Try again" cleared the failure and ran nothing. It
  now runs on the record that terminal keeps and its cached backend whatever is chosen
  (`keepsRecord(of:terminalID:)`). The same flaw hit "Detach from this Mac" the other way round
  (its terminal no longer chosen): its retry now repeats it on the backend that ran it while
  that backend keeps the record (`lastDetachTerminalIDs`); with the same terminal still chosen
  it is as before. Regressions `aDetachRetryKeepsItsTerminalAfterAChange`,
  `anITerm2DetachRetryKeepsITerm2AfterAChange`, `aDetachFromThisMacRetryKeepsItsTerminalAfterAChange`.
- **A missing script handler read as Ghostty's AppleScript turned off.** -1708 is also what a
  script answers for a handler it lacks, so the number cannot tell the two apart. A built-in
  script defines every handler, so there the line is unchanged; from a user definition or an
  override (`LoadedTerminalDefinition.source`, which the model now passes as
  `SessionProblem.attach`'s `definitionSource`) an open answering -1708 names both causes as
  possibilities ("… may have no “muxfinder_open” handler, or Ghostty's AppleScript may be turned
  off …", for other apps the handler only) with "Try again" and "Open Settings". -10004 is never
  a missing handler and keeps the AppleScript-off line. Every case still has its own line.
  Regressions `aMissingHandlerIsNotGhosttysAppleScriptTurnedOff`,
  `anOpenNobodyHandledIsWordedAsAPossibility`.

Changed test of this phase: `TerminalSessionModelTests.anotherTerminalsRecordDetachesThroughItsOwnBackend`
expected "Move here…" dimmed beside a window (`!opened.offersMoveHere`), which is the first
finding; it now expects it offered. No other expectation changed.
