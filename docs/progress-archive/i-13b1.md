## Review

Codex (`autoclaude-review.sh`, 20 min) → `ship-with-fixes`, 2 blockers, 0 should-fix —
`docs/reviews/phase-I-13b1.md`:

1. *The verified result was not bound to the checked bundle* (versions reopened by path, the
   path returned without an identity check). Fixed: the shape walk keeps the folder open and
   records device and inode; the identity is required before and after the code check and
   after the versions read (`bundleChanged`, "the download changed while it was being
   checked"); versions read through the open folder; the result carries the identity; D39
   requires I-13b2 to compare it and re-run the code check right before the swap. Regression:
   2 verifier tests fail with the fix reverted.
2. *Expansion limits only after extraction* (a zip bomb could fill the disk inside the time
   bound). Fixed: the pre-check of the central directory and local headers before `ditto`,
   and the watchdog during it. Regressions: 3 archive tests fail without the pre-check, 2
   without the watchdog.

Both fixes re-verified by the orchestrator (build, lint, full suite, real zip-mode run).

## Decisions (workers')

- `Accept-Encoding: identity` on the download, so `Content-Length` is the file's size.
- `--running-build` defaults to 0 in the probe.
- `ditto` takes names from local headers and extracts entries the directory does not list, so
  the pre-check requires every local header to match its directory record, with no gaps or
  overlaps; a deflate stream that ends earlier than declared is left to the watchdog and the
  shape walk.
- Wrong top levels are refused by the pre-check (`outsideApp`); bytes that are not a zip fail
  as `malformed`; the shape rules are tested on hand-made folders (`ditto` refuses an empty
  zip and writes FIFO entries as plain files).

## Open risks / deviations

- **For the user:** the real `update verify --latest` (and so the real download and GitHub's
  current redirect hosts) is checklist item 30; a download host outside the allowlist fails
  safely with a typed reason.
- A size lie that finishes within one 50 ms watchdog interval is caught only by the final
  measure after `ditto` ends (the pre-check's local-header rule narrows what can lie); proven
  mid-run stop with a fake runner and a one-off 512 MiB real run outside the suite.
- The contents of the checked bundle can still be changed by another process of the same user
  inside the private 0700 staging folder after the check: I-13b2 closes it (identity compare
  and code check again right before the swap, D39).
- The implementation worker's first failing test runs left 13 test folders in `/private/tmp`
  (removed; helpers fixed). The review-fix worker ran one read-only `git diff --stat`, against
  its brief.
