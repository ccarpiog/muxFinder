## Decisions

- **D24** (onboarding trigger and save rules, the `sshSetup` request kind, helper mode and
  argv, validation points, the hold, where the action is offered, `SSHSetupLauncher` over
  `LaunchTab`). Rejected: optional session fields on `LaunchRequest` (would change how attach
  requests decode).
- The helper treats any ssh exit but 255 as success (only 255 means ssh itself failed; other
  statuses are the remote shell's).
- Onboarding edits names, destinations, This Mac and "Turned on" only; the rest stays in
  Settings.

## Review

Codex → `ship-with-fixes`, 0 blockers, 2 should-fix, both in
`Sources/MuxFinderUI/Model/SSHSetupActions.swift`:

1. Closing Settings or onboarding called `cancelAll()`, which dropped every task handle at
   once although cancellation does not finish them (`LaunchTab.open` awaits independent
   work), so app shutdown could not await in-flight launches. Fixed: every request stays
   registered by request number until it ends; window close cancels but keeps it; quit
   cancels all and awaits each. Regression `quittingWaitsForRequestsOfAClosedWindow()` (a fake
   whose cancelled call keeps waiting at its gate) failed on the old code 3 of 3 runs.
2. An edit during an opening request (`clear(id)`) was ignored by the guard, so a late result
   for the old destination was published under the edited host. Fixed: each host's line waits
   for one specific request; `clear(_:)` and window close drop the link, so obsolete results
   are never shown and a new request can start at once. Regression `editsDropAPendingResult()`
   (onboarding destination edit, This Mac choice, Settings destination edit) had 5 failed
   expectations on the old code.

The fix worker confirmed old-code failures by temporarily restoring the original file. No
re-review (one review per phase).

## Open risks

- The real ssh-setup round trip (tab, interactive ssh, hold) is owed to a later real-run
  window, Saturno only; the probe's `ssh-setup` cannot yet close its own tab by session id.
- A destination changed and saved in Settings does not clear the popover's existing ssh-setup
  line for that host (noted by the fix worker, not addressed).
- "Retry" in the popover while a tab is opening now drops that line and its result and offers
  the button again (D24 says so).
- `quittingWaitsForRequestsOfAClosedWindow()` relies on two queued main-actor tasks running in
  order to make the old code fail; the fixed code passes in either order.
- Owed to a person: clicking through the onboarding window for real.
