7. **Pipeline** — met. prepare / install / discard with the states downloading, checking,

8. **Flag** — met. `build/muxFinder.app/Contents/MacOS/muxFinder --report-update-eligibility`

## Decisions (workers' calls, details in D39)

- No two-rename fallback, since `RENAME_SWAP` worked: a volume without it fails the swap with
  nothing changed.
- The relauncher takes the wait in seconds as a fourth argument (default 60) so tests prove the
  timeout quickly.
- Recovery-required marker in the run folder; cleanup keeps such folders.
- Process scan passes over zombies, `P_WEXIT` and `ENOENT` live processes (otherwise every
  cleanup on this Mac would stop: an unreaped zombie and a process running a replaced
  executable exist).
- A copied `/bin/sleep` run from a private folder is killed (exit 137) unless signed ad hoc, so
  the cleanup test signs its copy ad hoc.

## Open risks / deviations

- **For the user (I-13c's checklist item):** whether `/usr/bin/open`, started with only `PATH`
  in its environment, opens the new copy; the real update end to end (Developer ID build).
- If the `recovery-required` marker cannot be written, a later cleanup could delete that run
  folder (documented in D39).
- A run lock can look held just after release (a child being spawned keeps close-on-exec
  descriptors until exec; 512 of 20,000 trials); cleanup then keeps the folder (safe); tests
  repeat cleanup for at most 10 s.
- Flaky runs seen by the fix worker: one full `swift test` run hung (every process-spawning
  test stalled at about 4 s; killed after 1500 s, its private folder removed); the UI test
  `panelRootIsNoTallerThanItsLimit` failed once (4 pt) and passed alone; `theRealScan` failed
  once (fixed: waits for the child to start). Orchestrator: the known load-sensitive
  `answersAndEndsAtEndOfInput` (folder search) failed once in a full run and passed alone and in
  the next full run.
- `v0.3.0` (build 3) was released by the user from branch `release/0.3.0` (I-11b's tree,
  `1c037ea`), not merged to `main`, whose `scripts/build-app.sh` still says 0.2.0 build 2. The
  next release from `main` must carry a build above 3 (D35) for the updater to offer it to a
  0.3.0 install; for I-13c's release contract.
