## Acceptance criteria and evidence

- **Diagnosed.** A launch of the bundle binary from the shell shows the window too, in both
  private homes (empty, and one holding a valid `hosts.json` with every host off). It is
  SwiftUI's own `Settings` scene window: a temporary trace, removed before the fix, showed
  SwiftUI's `AppWindowsController.showInitialWindow()` opening it as launching finishes. The
  shell launch gets the same `oapp` launch event a Finder launch does, and no saved window
  state exists. ⌘, was never a main-menu item; it opens Settings only from the popover and the
  switcher, unchanged. — met (worker's runs, recorded in `docs/TESTING.md` before the fix).
- **No window at launch.** The menu bar app runs on a plain `NSApplication` with a hand-built
  main menu (`Sources/MuxFinderUI/Views/MainMenu.swift`): muxFinder menu (About, Services, Hide
  ⌘H, Hide others ⌥⌘H, Show all, Quit ⌘Q through `terminate:`), Edit (Undo ⌘Z, Redo ⇧⌘Z, Cut,
  Copy, Paste, Paste and match style ⌥⇧⌘V, Delete, Select all ⌘A), Window (Close ⌘W through
  `performClose:`, Minimize ⌘M; AppKit adds Close All, Zoom, Bring all to front and the window
  list). — met: the orchestrator's own shell check under an empty `CFFIXED_USER_HOME` listed the
  hidden popover panel and the onboarding window only ("muxFinder other windows: 2, 1
  visible"), SIGTERM exit 0, no child, the home still empty; the worker's run with the hosts-off
  home showed no visible window besides the menu bar item.
- **Nothing else changes.** Close is disabled for the popover and switcher panels, so ⌘W cannot
  close them. Differences from SwiftUI's old menu: Paste and match style and Close ⌘W are new;
  Help (⌘? said only that help is unavailable), the empty View menu and a hidden sidebar toggle
  are gone; menu titles are sentence case. Other launch modes keep their own shells: preview
  snapshots exit 0, `--selftest bogus-name` exits 2 having contacted nothing,
  `--report-popover-placement` once (offsets 0 and 0, check passed). — met.
- **The shell check sees it.** `--report-menu-bar-item` now prints every other window (title,
  class, visibility, level; never contents), the launch's Apple event and the main menu,
  through `Sources/MuxFinderUI/Model/AppShellReport.swift`, written off the main actor through
  `NonblockingLineWriter` (review fix). — met.
- **Tests.** `Tests/MuxFinderUITests/{MainMenu,AppShellReport}Tests.swift`, 12 new; no
  existing test changed. — met.
- **Docs.** `docs/TESTING.md` (before and after, both homes), `docs/MANUAL-CHECKLIST.md` item 19
  (launch from Finder and at login with no window; Edit shortcuts in the popover search field
  and Settings; ⌘Q quits), `docs/ARCHITECTURE.md`, the shell type's doc comment. — met. The
  `CLAUDE.md` command note is **owed** (see below).

## Review

Codex (`autoclaude-review.sh`, 15 min) → `ship-with-fixes`, 0 blockers, 1 should-fix: the
extended report's synchronous `FileHandle.write` on the main actor could block the UI and the
orderly shutdown behind a stalled stdout reader. Fixed inline by the orchestrator: the report's
lines go through a static `NonblockingLineWriter` (`Sources/MuxFinderApp/AppDelegate.swift`).
Not verified: a regression run against a full, undrained stdout pipe (the report is about 5 KB,
far below a pipe's 64 KiB, so it cannot be forced without a harness). A closed stdout still
raises `SIGPIPE` on the writer's queue, as the old write did; `SIGPIPE` is not ignored in the
normal app on purpose, since an ignored disposition would be inherited by every child it starts.
Report: `docs/reviews/phase-I-4.md`.

## Open risks / deviations

- **`CLAUDE.md` note owed.** `CLAUDE.md` carries the user's uncommitted NonameDownloads edit
  (named in the runner's preflight file), so the run neither edited nor committed it. Wording
  for its `--report-menu-bar-item` note: replace "prints the windows of muxFinder's own status
  item (PLAN.md D30; AppKit's replicas included) after 2 s" with "prints, after 2 s, the windows
  of muxFinder's own status item (PLAN.md D30; AppKit's replicas included), then every other
  window of the app (title, class, visibility, level; only onboarding may be visible, PLAN.md
  D33), the launch's Apple event and the main menu", and "contacts nothing; then" with "contacts
  nothing; nothing else may be visible; then".
- **Safety slip (worker).** One shell-check run had a mistyped `CFFIXED_USER_HOME` naming a
  nonexistent `/tmp` path. Nothing was created there; onboarding showed, so the real host list
  was not read; the real `hosts.json` and `preferences.json` still date from 2026-10-24.
- Phase 9b (macOS 27.2) saw no such window, so a later macOS probably introduced the behavior;
  unverified. Real Finder and login-item launches, and the Edit shortcuts in the real
  non-activating panels, are the user's (checklist 19).
