## Decisions (the workers')

- The Settings "Updates" section shows only when there is update machinery or a fixture, so it
  is hidden in diagnostic modes and in the older gallery states.
- The notice counts as seen only while the popover shows its main view, not while a Move here
  or Detach confirmation covers it.
- After the review fixes: the scheduler saves its state one write at a time, each write saving
  the state as it is when its turn comes; `markNoticeSeen` publishes the seen version only
  after its save succeeds (a failed save changes nothing, the dot stays); a check's save waits
  for a seen-mark save already running. A toggle change made while the setting is still being
  read wins over the value read; toggle saves run in order, each then telling the scheduler the
  current value; a refused save puts the toggle back to the saved value. An internal
  `savesWaiting` count exists for the tests (like `failedSaves`).

## Review

Codex wrote `docs/reviews/phase-I-13c1.md` (`autoclaude-review.sh`, 20 min budget) →
`ship-with-fixes`, 0 blockers, 2 should-fix:

1. `UpdateModel.swift` — startup overwrote toggle changes made during the preference load.
   Fixed (a change after start wins; saves ordered); regression with a held preferences read
   fails with the fix reverted.
2. `UpdateScheduler.swift` — `markNoticeSeen` published before its save, so a failed save could
   leave the dot cleared, and interleaved writes could lose fields. Fixed (serialized saves,
   publish after success); two regressions with a controllable store fail with the fix
   reverted (pending mark in the status, dot cleared, the late save overwriting the check's
   `etag`, release and dates).
