## Decisions

- Orchestrator (in `PLAN.md` before the worker): core only, nothing rewired; pid reuse refused by
  the controlling terminal's device and the start time against `client_created` (1 s rounding);
  iTerm2's job server (`~/Library/Application Support/iTerm2/iTermServer-*`, parent iTerm2 or
  launchd, verified on Neptuno) names iTerm2; with D16's index in use, iTerm2's control-mode
  clients are left to it; app activation only of a running app; the plain backend's attach
  focuses an attributed app instead of opening, the iTerm2 backend's attach unchanged
  (requirement 12).
- Implementation worker: an extra unmapped reason `incompleteClient` (no usable terminal or
  creation time); a parent started after its child is `processGone`; bundle identifiers compared
  without ASCII case; the real home via `getpwuid_r`; `LocalTerminalApp` refuses an app that is
  neither iTerm2 nor a definition's; the plain backend's attributor and activator default to nil
  so the I-12c1 tests stay unedited (I-12c3 passes them); `TerminalAppActivating` made
  `Sendable`; `ITerm2TerminalBackend` gains an optional `appActivator` used only for `.app`
  handles; one `appFocused` case in each of the two exhaustive `MuxFinderUI` switches (shown as
  focused).
- Review-fix worker: the terminal and creation time moved out of the client line into a
  nonce-framed `tty` record after it (`tty <nonce> <pid> <created> <tty> <nonce>`, a terminal
  over 255 bytes printed as nothing by tmux), parsed like D31's `path` record; the client line is
  five fields again; `maximumReportSize` counts the record (324 bytes per client); D31's output
  cap figure updated (about 12.1 MiB).

## Open risks / deviations

- No client in Terminal or Ghostty traced for real (neither is used on this Mac; Ghostty not
  installed, its chain unverified) — owed with I-12c3's real runs or the user.
- Nothing calls the attributor yet: `AppModel`, `AppEnvironment` and the self-tests are wired in
  I-12c3; the plain backend's attributor defaults to off until then.
- A session open by hand in another terminal app is focused by app activation only (no window
  chosen); a focus by terminal path (Terminal's `tty` property, iTerm2's session variable) is a
  later candidate, not planned.
- macOS 14's cooperative activation may refuse `activate(options:)` from a background app; the
  outcome is recorded and never fails an attach, but how often it refuses is unseen (I-12c3 /
  the manual checklist).
- The review fix edited one existing test (`ProbeSessionPathTests
  .theOutputBudgetHoldsTheLargestAcceptedReport`): its 1,000 clients gained the longest `tty`
  record and it also expects every terminal and creation time back; its earlier expectations
  kept.
