## What was built

- `Sources/MuxFinderCore/Tmux/`:
  - `ProbeScript` — one static POSIX `sh` script; its only argument is the optional tmux
    override. Emits the versioned report (`MUXFINDER-PROBE 1`, `uname -n`, tmux path or
    not-found marker, tmux version, `list-sessions` exit status, first stderr line sanitized to
    printable ASCII, terminator). Each record line carries a random per-run token so a session
    name cannot forge a record; `session_name` is the last field. Unsets `TMUX`/`TMUX_PANE`.
    All tmux calls use `tmux -u` (D12). tmux stderr and `tmux -V` output are bounded to 200
    bytes inside the shell with the real exit status returned on a separate fd (no temp files).
  - `TmuxLocator` — override used alone (no fallback); otherwise searches `/opt/homebrew/bin`,
    `/usr/local/bin`, `/usr/bin` and `command -v`; the candidate must answer `-V` like tmux (D5).
  - `ProbeReport` — strict parser: ids `^\$[0-9]+$`, strict integers, name = remainder after
    the fixed fields; > 1,000 sessions, lines > 4 KiB, missing header/terminator, unknown
    version or inconsistent records → `probeError`, never a crash.
  - `TmuxModels` (`ServerIdentity`, `DiscoveredSession`, `ClientSummary`, `SessionKey`),
    `HostStatus` (all PLAN cases), `ErrorClassifier` (ssh exit 255 + stderr patterns; "changed"
    host key wins over "verification failed"; no-server messages; runner timeout →
    `unreachable(.timeout)`).
  - `DiscoveryProbe` — local runs through argv with `TMUX`/`TMUX_PANE` stripped; SSH runs via
    `/usr/bin/ssh` with `BatchMode=yes`, `ConnectTimeout=5`, `--` before the destination, the
    remote command built only by `ShellQuoting.remoteCommand` (D3); 12 s runner backstop. A
    strict host-key harness policy (test option only) adds `StrictHostKeyChecking=yes`, a given
    `UserKnownHostsFile`, `GlobalKnownHostsFile=/dev/null`, `ControlMaster=no`, `ControlPath=none`.
- `Sources/MuxFinderCore/Config/HostConfig.swift` — model only (persistence is Phase 7).
- `Sources/muxfinder-probe/DiscoverCommand.swift` — `discover --local | --ssh <dest>
  [--tmux-path <p>] [--raw] [--strict-known-hosts <file>]`, JSON output.
- Tests: `DiscoveryEndToEndTests` (real tmux on a private `/tmp` socket, cleanup in an
  uncancelled task with bounded timeouts, cancellation test), `DiscoveryProbeTests`,
  `DiscoveryTestSupport`, `ErrorClassifierTests` (table over captured ssh stderr),
  `ProbeReportParserTests` (fixtures, hostile names, malformed/oversized input, single-byte
  corruption), `ProbeScriptTests` (stderr flood bounded with exit status preserved, peak-memory
  check, endless `-V` line, hanging probe stopped).
- Fixtures `Tests/MuxFinderCoreTests/Fixtures/discovery/` — 6 real captures (local and Saturno,
  only `muxfinder-test-*` names) plus 1 synthesized hostile-name report.
- `docs/TESTING.md` — real checks with dates, commands and observed results.

## Decisions

- **D12 (new):** every tmux call goes through `tmux -u`. Without a UTF-8 locale tmux replaces
  non-ASCII bytes *and* the tab separators with `_`, so the report cannot even be split; SSH
  only forwards a locale when the client has `LANG` set, which a GUI app normally lacks.
  Confirmed locally and over SSH to Saturno.
- **D5 edited:** an explicit override is used alone (no fallback); `/usr/bin/tmux` added to the
  search list; the found file must answer `-V` like tmux.
- **D3 clarified:** a static script run locally through `/bin/sh` with data passed only as
  positional arguments is the local counterpart of the remote rule.
- **D11 edited:** the hermetic suite may run real tmux on a private socket under `/tmp`.
- `--` before the ssh destination is used (OpenSSH_10.5p1 accepts it) in addition to
  validating the destination; the orchestrator's brief had wrongly said it was invalid.
- Discovery is not strictly write-free: any tmux command creates the `tmux-<uid>` socket
  directory when it is missing. Recorded in *Verified facts*.

## Acceptance

All met:
- Fixture tests: real captures, Unicode, hostile names (`a;rm -rf ~`, `$(touch /tmp/x)`, quotes,
  tabs, `-x`, emoji, `#{pid}`, backslash), malformed/oversized → `probeError`, classifier
  table test. Two classifier rows ("No route to host", "Network is unreachable") use standard
  OpenSSH wording rather than captures, marked so in the test.
- Real checks in `docs/TESTING.md`: local no-server (private `TMUX_TMPDIR`) → `noServer`; local
  test sessions incl. Unicode → `ok` with exact ids; Saturno → `noServer`, then `ok` with test
  sessions; `.invalid` → `dnsFailure`; `192.0.2.1` → timeout after 5.0 s; auth failure →
  `authFailed`; host key unknown/changed → `hostKeyProblem`; extra `ssh://127.0.0.1:1` →
  `refused`. The orchestrator re-ran the unknown-host-key check after `ControlPath=none` was
  added (same result) and a normal Saturno probe (`noServer`).
- No leftover `muxfinder-test-*` sessions or tmux processes on Neptuno; Saturno reports no
  server.

## Review findings and resolutions

1. Shell captured all tmux stderr before truncating it (bypassed the 1 MiB runner cap) → stderr
   now bounded to 200 bytes in-shell, exit status preserved via a separate fd; regression tests
   for an 8 MiB flood (exit 3 kept, 200-byte line) and peak memory under 8 MiB (2.5 MB after,
   119 MB before). `tmux -V` capture bounded too.
2. End-to-end test cleanup ran in the cancelled task, so it could leak sessions → cleanup in an
   independent task with 5 s per command and a 20 s overall bound, before the socket dir is
   removed; `cleansUpWhenTheTaskIsCancelled` test added.
3. Strict host-key harness inherited the user's `ControlPath` → `ControlMaster=no` and
   `ControlPath=none` added to the harness policy only; request tests assert it and that normal
   requests carry no `Control*` options.
