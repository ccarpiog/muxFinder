## What was built or fixed

- **Audit before any real run:** the coordinator and the `e2e-local` harness already waited
  10 s before every detach, kill or close they cause. iTerm2 3.7.6's short-lived-session
  threshold was read from the installed iTerm2 binary, read-only: **3 s**. The default
  profile's warning is not silenced; no preference was written.
- **Helper lifetime gap (`LaunchHelper.swift`):** the helper could exit at once when tmux ended
  right after attaching, or when Return was pressed straight after a refusal. It now never
  exits before it is `minimumLifetime` (10 s) old while its tab is visible (interactive
  terminal, not hung up), and writes its result file before that hold. D14 edited.
- **`e2e-local`:** step 8 (stale guard) fails if the refused launch tab closes by itself. The
  test closes that tab, which it created, by the iTerm2 session id it was given, and only after
  10 s. Every step records how old the launch tab was when it ended.
- **Review fix (SIGINT/SIGTERM):** see *Review and fixes*.
- **Docs:** `docs/INTEGRATION-PROOF.md` is final (no draft wording). It records versions,
  per-step timings and observed behaviors. `docs/TESTING.md`, `CLAUDE.md` (run `swift build`
  before real runs) and `PLAN.md` (D14, D15, *Verified facts*) were edited in place.

## Review and fixes

Codex → `ship-with-fixes`, 0 blockers, 1 should-fix (`docs/reviews/phase-4c.md`):

- **SIGINT/SIGTERM bypassed the 10 s minimum lifetime.** `waitForReturn()` and
  `holdOpen(for:)` restored `SIG_DFL` for SIGHUP, SIGINT and SIGTERM, so Ctrl-C at the failure
  prompt killed the helper at once while its tab was visible.
- **Fixed by a fix worker:**
  - Both waits restore only SIGHUP's default, so a closed tab still ends the helper at once.
    SIGINT and SIGTERM stay ignored.
  - At the failure prompt, SIGINT or SIGTERM ends the wait like Return, and the hold for the
    rest of the lifetime still follows. `LaunchWaitGate` ensures the wait resumes exactly once.
  - During the hold, SIGINT and SIGTERM do nothing.
  - New pseudo-terminal suite "Launch helper binary (terminal)" (`PseudoTerminalHelper` in
    `LaunchTestSupport.swift`). Its 4 SIGINT/SIGTERM cases failed with the old behavior put
    back; the SIGHUP cases passed both ways.
  - New test-only setting `MUXFINDER_LAUNCH_MINIMUM_LIFETIME_MS` (1–7 digits, otherwise
    10 s), documented in D14 and `docs/TESTING.md`. Its prefix keeps it out of tmux's
    environment.
  - Re-verified, including real run 4. No re-review (one review per phase).

## Consequences for later phases

- `swift run muxfinder-probe` does not rebuild `muxfinder-launch`, the helper iTerm2 runs.
  Always `swift build` before a real run, or it launches a stale helper. This is documented,
  with no automatic guard.
- Abort, failure-step and signal cleanup in `e2e-local`, and recovery of a session created
  during cancellation, have still only run hermetically. An aborted real run was not risked,
  because a mistake there would block iTerm2 again.
- Product trade-off: when the user detaches within 10 s of attaching, the launch window stays
  open until the 10 s are up. Phase 10/11 may revisit this, for example with a profile that
  silences the warning.
- A Ctrl-C landing in the instant between the failure prompt appearing and the wait watching
  for signals is ignored; the wait continues until Return or the next Ctrl-C.
- `MUXFINDER_LAUNCH_MINIMUM_LIFETIME_MS` would also shorten the lifetime in a real launch if
  it were present in iTerm2's environment. It is test-only by convention.
