## Decisions (D38, details in `PLAN.md`)

- **Remote identification works**: the remote client is told apart by the launch token in its
  parent shell's argv, read with `ps` by `client_pid` over BatchMode ssh (read-only, no remote
  write). Remote plain attaches can end confirmed.
- **Move here in plain mode is `attach-session -d`** (one atomic tmux command; D37 rejected it
  only because of iTerm2's control connection).
- **Bound commands (review fix)**: every attach and detach is one `if-shell -F -t '<id>'
  '<cond>' …` command, the condition checking the session's id, creation time, server pid and
  start time, socket path and name and, for a detach, exactly one client with that name, pid
  and creation time; otherwise a marker (detach) or exit 65 (attach), nothing done. The old
  unbound local attach builder was removed so I-12b cannot reuse it.
- Notes for later sub-phases: pty paths are reused once the controlling process exits, so the
  local match must check the attach child's pid too (I-12c); tmux draws through the client's
  stdin, so it must be opened read-write (I-12b); I-12b names Ghostty's token variable.

## Review

Codex (`autoclaude-review.sh`, 15 min) → `ship-with-fixes`, `docs/reviews/phase-I-12a.md`:

- BLOCKER: the harness's detach could hit a replacement client after tty reuse (check and
  detach separate). Fixed by the bound detach above; regressions `buildsTheBoundDetach` and
  `bindsTheDetachOnAPrivateServer` fail with the fix reverted.
- SHOULD-FIX: local attaches trusted a session id without revalidating the server. Fixed by
  the bound attach (also applied to the remote script after its guard); regressions
  `buildsTheBoundLocalAttach`, `bindsTheAttachOnAPrivateServer` and PlainLaunchTests fail
  with the fix reverted.
- Residual: tmux picks a `detach-client` target by name only, so the detach relies on the
  name's uniqueness, which the same command checks. The remote bound attach's refusal is
  covered indirectly (its arguments equal the local builder's, which are tested on a private
  server).
