# Phase I-12b2 — Other terminals: helper plain mode, request terminal field, early report

Closed 2026-11-06. Risk class **high**. Worker model: **opus** (one implementation worker);
the review's should-fix applied inline by the orchestrator (test-only, three lines).

## Selection

I-12b2 as planned ("terminal seam and helper plain mode") was two workers' worth, with two
independent halves, so the orchestrator split it at selection, before the worker (recorded in
`PLAN.md` *Phase I-12*, "I-12b split"): **I-12b2** — helper plain mode (requirement 4),
requirement 5's early report and the request's terminal field; **I-12b3** — the terminal seam
(requirement 2), its calls to be written at its selection. The orchestrator's calls for I-12b2
are in `PLAN.md`, block "Calls for I-12b2 (helper plain mode; 2026-11-06, before its worker)".

## Acceptance criteria and evidence

1. `muxfinder-launch attach-plain <uuid>` and `profile-plain <host id>` exist; `attach`,
   `profile`, `ssh-setup` unchanged — **met**: the five mode words are named constants
   (`LaunchHelperMode`); every existing test passes with its expectations unchanged (one
   existing round-trip test's key set grew by `terminal`, an addition); `e2e-local` 16/16 and
   `e2e-bury --local` 13/13 against real iTerm2 on the final code.
2. The request's `terminal` field — **met**: always written (`"iterm2"` or a definition id by
   `TerminalDefinition.isValidID`), missing reads as `iterm2`; `attach` and `attach-plain`
   refuse each other's requests with exit 72 and run nothing; `keepsMinimumLifetime` on an
   iTerm2 request makes it unreadable (tested).
3. Plain attach argv — **met**: equal to `PlainLaunch.localAttachArguments` locally and D17's
   `ssh -t` with `PlainLaunch.remoteScript` / `remoteMoveHereScript` and the token remotely; a
   move here is told apart as for iTerm2, by the request's existing `detachOtherClients: true`
   (tested).
4. Plain mode's terminal output — **met**: no OSC 1337, no status report request, no bury;
   result file, explanation and wait for Return kept; the 10 s minimum only with
   `keepsMinimumLifetime` (tested). The attach child's standard input is the helper's terminal
   reopened read-write (`TerminalChildRunner`'s new `standardInput: .terminalReadWrite`); with
   the reopen disabled the real tests failed and tmux drew under 200 bytes.
5. The early report — **met**: `<uuid>.report.json`, schema 1, `id`, `helperPID`,
   `terminalPath` (absent when standard input is not a terminal), `attachChildPID`,
   `attachChildStartTime {seconds, microseconds}`; written atomically 0600 right after the
   spawn; `LaunchStore.peekReport` never deletes it; removed when the result is taken, by the
   sweep, or with `removeReport` (deliberately not by `discardRequest`, so a withdrawn request
   never deletes a running helper's report); malformed or oversized → typed errors (tested).
6. The real plain attach of the built helper — **met**: `realPlainAttachOnAPseudoTerminal`
   in `swift test` (a pty of the test's, a `muxfinder-test-*` session on a private
   `TMUX_TMPDIR` server, private launch directory, test mode, no wait): report terminal = the
   pty, child pid = the attach child (the helper's child, start time matching), exactly one
   client with that `client_tty`, tmux drew on it, the bound `PlainClientDetach` ended it, the
   helper wrote a success result and exited 0, nothing left. Passed with the debug helper and
   with the bundle's (through the test-only `MUXFINDER_TEST_LAUNCH_HELPER` override).
7. Build, lint, tests, bundle — **met** (see *Verification*).

## Decisions

- Split of I-12b2 into I-12b2 / I-12b3 (above).
- The orchestrator's calls (`PLAN.md`): explicit mode words, never guessed from the
  environment; `terminal` field with the missing-means-iTerm2 rule and exit 72 refusals;
  `keepsMinimumLifetime` only on plain requests; the bound plain attach from `PlainLaunch`
  only; the report's fields and its peek; `profile-plain` as `profile` without `-CC`; real
  pty check; regression `e2e-local` and `e2e-bury --local` by the orchestrator.
- The worker's: a move here keeps the existing `detachOtherClients` marker; the report is not
  removed by `discardRequest`; `LaunchChildRunner` gained `standardInput:` with a default that
  ignores it (only `TerminalChildRunner` honors it), so existing fakes compile unchanged; the
  usage line keeps the literal `profile <host id>` (an existing test checks it);
  **`profile-plain` keeps `profile`'s 10 s hold** (no request carries the flag) — harmless
  outside iTerm2, recorded for I-12d to revisit when it shows the per-host command.
- Records: D14 *Plain modes*, D38 "Helper plain mode (I-12b2)", `docs/TESTING.md` *Phase
  I-12b2*, `CLAUDE.md`'s launch helper line.

## Review

Codex (`autoclaude-review.sh`, 20 min) → `ship-with-fixes`, 0 blockers, 1 should-fix
(`docs/reviews/phase-I-12b2.md`): the real-pty test's private tmux server started without
`-f /dev/null` and with the real `HOME`, so `swift test` could run the user's `tmux.conf`
(plugins, `run-shell`) and leave processes behind. **Fixed by the orchestrator**: `-f
/dev/null` on the server-starting `new-session` in `LaunchHelperPlainBinaryTests.createSession`
and, for the same flaw from I-12a, in `PlainBoundCommandsTests.Server.create`; the new test's
`HOME` is its private socket folder. Re-verified (lint, full `swift test`, the two suites with
the real-pty test shown running and passing). No re-review (one per phase).
