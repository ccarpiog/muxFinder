## Scope and split

worker's first real run (43.2 s, exit 1) passed steps 1–4 and failed step 5: it detached about
1 s after attaching, the launch tab and tmux tabs ended within ~1.5 s of starting, and iTerm2
opened its modal "session ended very soon after starting" warning in the launch window the test
had created. While that warning is open iTerm2's API answers nothing (`muxfinder-probe iterm2
status` → `timedOut`, exit 75, re-checked by the orchestrator at 01:13 and 01:39 on
2026-10-22). Only a person can dismiss it (no UI scripting, run rule 6), so the real proof moved
to a new **Phase 4c**, recorded in `PLAN.md` "### Phase 4" Split paragraph. 4b closes on its
code, hermetic tests and the draft proof doc.

## Review and fixes

Codex found 3 blockers and 2 should-fix; a fix worker resolved all five:

1. Identity-failure cleanup detached at once → the coordinator now sends `detach-client` only
   once the launch tab is 10 s old (identity failure and every `detach`; 10 s from the call for
   a tab it did not open; a cancelled wait sends nothing). Tests:
   `identityFailureDetachWaitsForTheMinimumAge`, `detachWaitsUntilTheLaunchTabIsOldEnough`,
   `detachCancelledDuringTheWaitSendsNothing`.
2. Detach by cached short connection id could hit a user attachment after an iTerm2 restart →
   identity check and detach go through `sendTmuxCommand(_:connectionID:ownedBy:)`, which
   re-lists connections and refuses (`tmuxConnectionNotOwned`) unless the owner is the recorded
   gateway session. Tests: `detachRefusesAConnectionNoLongerOwnedByTheLaunchTab`,
   `ownedTmuxCommand`, `fakeOwnedTmuxCommand`.
3. Harness rediscovery by `$id` alone → every later discovery, survival check and kill requires
   the full `CreatedSession` identity. Test: `CreatedSessionTests` (harness wiring not run for
   real).
4. An older cancelled flight could overwrite a newer flight's state → only the newest launch
   sets session state (`isCurrent`). Test: `olderCancelledLaunchDoesNotOverwriteTheNewerState`
   (shown to fail with the gate removed).
5. Cancellation during `new-session` skipped cleanup → cleanup recovers the session by its exact
   generated name among sessions created since the attempt, re-checks, kills by id. Test:
   `CreatedSessionTests.findsTheSessionByItsExactName` (harness wiring not run for real).

## Consequences for later phases

- `muxfinder-probe detach` needs `--gateway` and always waits 10 s (a separate process cannot
  know the tab's age); the app hits the same wait for tabs opened before a restart.
- An identity failure reports its result ~10 s after the tab opened.
- Unverified: whether the socket path discovery reports equals the one `new-session -P` prints;
  if not, 4c step 2 fails safely (nothing attached).
- Phase 11's muxFinder dynamic profile could silence the short-lived-session warning — a
  product decision for that phase, not taken here.
