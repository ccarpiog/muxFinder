## Delivered

- `scripts/install.sh` — installs `build/muxFinder.app` into `/Applications`, or
  `~/Applications` with `--user`; copies with `ditto` into a hidden temporary sibling, verifies
  the copy, stops a running copy at the destination (SIGTERM to that copy's `muxFinder` only,
  bounded 20 s wait; refuses and changes nothing if it does not quit), then swaps by rename.
  Never launches the app. `--dry-run`.
- `scripts/uninstall.sh` — stops only each copy's `muxFinder` (helpers `muxfinder-launch` are
  reported and left: they hold the user's iTerm2 tabs), removes the app copies, removes
  `DynamicProfiles/muxFinder.json` only through the bundled binary's new
  `--remove-persistent-profiles [--dry-run]` (D26 ownership check under the lock; a copy is run
  only if its Info.plist declares `MuxFinderScriptInterface 1` and its signature is valid;
  without one the file is left and its path printed), removes
  `~/Library/Application Support/muxFinder` (never through a symlink), removes the app's
  preferences domain `cc.carpio.muxfinder` with `defaults delete` only when it exists and never
  in dry run or test mode, prints how to clear the login item and the `tccutil reset
  AppleEvents` command for the user. Never touches tmux, iTerm2 preferences or other profiles.
- Shared library `scripts/lib/app-copies.sh`; test overrides `MUXFINDER_TEST_HOME` and
  `MUXFINDER_TEST_APPLICATIONS` (set together, physical private folders only).
- `scripts/dev/test-install-scripts.sh` — hermetic check on private `mktemp -d` folders with a
  compiled C stub as the process stand-in (a copy of `/bin/sleep` run from another path is
  killed by macOS, exit 137); 35 steps after the review fixes.
- Swift: `Sources/MuxFinderCore/Profiles/PersistentProfileRemoval.swift`, the app flag in
  `Sources/MuxFinderUI/Model/AppLaunchOptions.swift` and
  `Sources/MuxFinderApp/MuxFinderMenuBarApp.swift`; tests
  `Tests/MuxFinderCoreTests/PersistentProfileRemovalTests.swift`, `AppModelTests`,
  `PersistentProfilesSettingsTests`.
- `scripts/build-app.sh` — Info.plist `MuxFinderScriptInterface`; the closing line now names
  the real signer (it used to say "signed for development" after an ad hoc fallback).
- `README.md`, `docs/ARCHITECTURE.md`, `docs/MANUAL-CHECKLIST.md`, the tested vs
  expected-to-work matrix at the top of `docs/TESTING.md` (its "12b fresh run" column reads
  "owed" on every row for 12b to fill), `CLAUDE.md` Commands, `PLAN.md` **D27** and the

## Review and fixes

Codex → `ship-with-fixes`, 3 blockers, 0 should-fix. All fixed by a review-fix worker, each
regression failing with its fix reverted (check steps 25–27, 28–30, 32–33) and passing with it:

1. `lsof` `txt` records include memory-mapped files, so a process merely mapping the
   executable was taken for a running copy → `lsof` only finds candidates; a process qualifies
   only if the kernel reports that file as its executable (`codesign -dv <pid>`, since `ps -o
   comm` is argv[0]); one whose executable cannot be established is named, never signalled,
   and the run refuses after the wait while it stays.
2. Test roots did not contain destructive operations (the real `~/Applications` was accepted)
   → in test mode both roots must physically lie under `/private/tmp` or
   `/private/var/folders`, owned by the user, not writable by others, outside the real home and
   `/Applications`; every derived path is checked beneath them with no symlink component
   before any action, else exit 2.
3. Deletion was not bound to the inspected folder → device/inode recorded at inspection, the
   folder renamed into a hidden sibling, compared, and only then deleted; anything else is put
   back and the run fails (exit 1). Applies to install's old copy and temporary folder and to
   uninstall's app copies and support folder. Test-only swap hook `MUXFINDER_TEST_SWAP_AT` /
   `MUXFINDER_TEST_SWAP_WITH`, refused outside test mode.

## Deviations and open points

- `shellcheck` is not installed; only `bash -n` ran.
- The "no symlink on the way" rule applies in test mode only; real runs follow links the user
  may have in their home or Library.
- For an uninstalled copy, the swap regression proves only that the swapped-in folder survives.
- The README's Gatekeeper statement about quarantined copies is untried (manual checklist).
- Neither script has run for real on this Mac's `/Applications`, `~/Applications`,
  `DynamicProfiles/` or support folder (by design; a real install/uninstall is the user's).
