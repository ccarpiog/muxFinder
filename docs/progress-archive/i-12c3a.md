front (I-12c1's open question); the iTerm2 backend's attach never consults ancestry (I-12c2's
open question, settled by requirement 12); self-tests forced to iTerm2; `attach --terminal
<id>` with its own rule-8 gate; the `e2e-*` harnesses unchanged.

## Decisions (the workers')

- A fourth unavailable reason, `versionUnknown` (the window layer also refuses an unreadable
  version).
- The setter goes through a new `TerminalSettingStoring` sub-protocol, so existing preferences
  fakes needed no change.
- The refresh engine is not rebuilt on a choice change; `setAttachmentChecksEnabled(_:)`
  switches D16's index off and on.
- Persistent profiles' Install and Remove buttons still work with a plain choice; only the
  automatic rewrites are gated (I-12d decides that tab).
- The probe's `attach` prints usage for `--help` and rejects empty option values.
- Review fixes (all in D38 "Onto the seam (I-12c3a)"): `TerminalBackend` reports read-only
  whether it holds an unresolved launch for a key (`AttachCoordinator.hasUnresolvedLaunch(for:)`
  added, read-only), and Open / Move here are refused with the existing "earlier launch
  pending" failure while any other cached backend holds one; the choice is explicitly
  `unresolved` until launch reads it, behaving as "not iTerm2"; an unattended run policy in
  the window layer rechecks "running and granted" right before the request write and every
  Apple event or spawn (the probe sets it); attachment records partitioned per terminal and
  session, rows and actions using only the chosen terminal's.

## Open risks / deviations

- Fix 1 refuses only Open and Move here (detaches start no attach); its message still says
  iTerm2 (I-12d's wording). An ended iTerm2 launch counts as settled only once its helper's
  result exists: a helper that dies without writing one keeps that session refused in other
  terminals for the app's life.
- The model no longer offers Detach from iTerm2 records while another terminal is chosen
  (records kept, reachable after switching back).
- While the choice is unresolved, an SSH-setup click shows "not used with this terminal"
  (cleared if it resolves to iTerm2).
- One review-fix worker full `swift test` run failed once in `FolderSearchTransportTests` on
  its "< 2 s" timing check under load (untouched code, known load-sensitive); passed in every
  later run, including the orchestrator's.
- No plain real run (I-12c3b). Ghostty is now installed on this Mac (it was not in I-12c2).
- The worker saw 1 buried session in `iterm2 list-sessions` not from its runs (no baseline
  taken then); the orchestrator's baseline before its runs read 0, and 0 after.
