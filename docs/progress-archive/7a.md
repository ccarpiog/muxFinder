# Phase 7a — host configuration (archived narrative)

Risk `routine`; workers: opus implementation + opus fix worker; orchestrator fixed one
pre-existing flaky test. Phase 7 was split into 7a (host configuration) and 7b (refresh
engine) in `PLAN.md` before the first worker, because neither opens iTerm2 windows and both can
run while 6a's final-tree `e2e-remote` waits for iTerm2's thread count to fall.

## What was built

- `Sources/MuxFinderCore/Config/HostList.swift` — the host-list value type: unique ids, at most
  one This Mac (local mode), no enabled SSH host without a valid destination; typed errors. The
  This Mac switch makes the chosen host local and enabled, and the previous This Mac SSH and
  disabled, keeping its destination. Onboarding defaults: Saturno, Neptuno and Sirio as SSH
  entries with empty destinations, disabled, none local (fresh ids on every load until saved).
- `Config/HostStore.swift` — an actor keeping `hosts.json` as `{"schemaVersion": 1, "hosts":
  [...]}`. Loading writes nothing and reports saved, not saved yet, or invalid with a reason.
  A save writes a flushed 0600 temp file and publishes it with one `renameatx_np`
  (`RENAME_SWAP` over an existing file, `RENAME_EXCL` when none, switching on `ENOENT`/`EEXIST`,
  at most 8 tries). The displaced file is deleted only when it is valid and byte-identical to
  what this store last loaded as saved or wrote; anything else is renamed (never copied) to a
  fresh 0600 backup `hosts.backup-<UTC>[-n].json` that never replaces an existing backup. If no
  backup name works, the displaced file stays at its hidden temp name and the save throws
  `displacedFileNotKept` (the new list is already saved).
- `Config/PrivateStorage.swift`, `Config/ExtendedACL.swift` — the launch layer's 0700/0600,
  ACL-stripping and safe-write code, factored out of `Launch/LaunchStore.swift` (which keeps its
  D14 behaviour) and shared with the host store. Every host-list save strips inherited ACLs from
  the `muxFinder` directory and the replaced file (a deny-delete ACL entry otherwise makes the
  publish fail with `EACCES`, measured).
- `Config/SSHConfigSuggestions.swift` — read-only `Host` names from `~/.ssh/config` and its
  `Include`s: case-insensitive keywords, `Keyword=value`, several patterns per line, quotes,
  comments; patterns with `*`, `?` or a leading `!` excluded; `Include` globs, `~/` and
  `~/.ssh/`-relative paths, several per line, depth limit 16, cycle protection, missing files
  skipped, followed inside `Match`; per-file size cap; de-duplicated in first-seen order.
- Probe: `muxfinder-probe hosts show [--config <path>]` and `hosts suggestions`
  (`Sources/muxfinder-probe/HostsCommand.swift`), read-only JSON.
- Docs: **D19 — Host configuration** in `PLAN.md`; `docs/TESTING.md` real checks; `CLAUDE.md`
  Commands.

## Acceptance (all met)

- Hermetic tests: round trip; 0600/0700 with ACLs stripped; missing file → defaults, nothing
  written; invalid JSON, unsupported schema and invariant-breaking files reported with nothing
  written on load, and the next save leaving a byte-identical backup; a file replaced between
  examination and publication (invalid, valid-but-changed, edited in place, appeared from
  nothing) preserved in a backup via a `beforePublishing` test hook — these regressions fail
  with publication turned back into a plain rename; a normal save over the store's own file
  leaves no backup; the This Mac switch; enabling an incomplete SSH host refused; defaults;
  every suggestion rule.
- Real read-only checks: `hosts show` reported `notSavedYet` and the real
  `~/Library/Application Support/muxFinder/` listing was identical before and after (worker and
  orchestrator, twice); `hosts show --config <private invalid file>` reported `notJSON` with
  the file's hash unchanged; `hosts suggestions` exit 0 (output only counted, no names
  recorded), `~/.ssh` unchanged. No iTerm2, tmux or ssh involved.

## Review

## Flaky test fixed (pre-existing, Phase 5b)

`aSilentRemoteConnectionIsStale()` (`Tests/MuxFinderCoreTests/RemoteAttachTests.swift`) failed
about once in 18 full runs: its wait condition (`clock.waiting >= 1`) could let the clock
advance while the remote connection's answer and its 3 s timeout were both pending, so the
timeout won. `GatedAttachClock` now counts sleeps cancellation ended or prevented, and the test
waits until the remote connection's timeout was cancelled (its answer won) and only the silent
connection's waits. 20 consecutive full-suite runs passed afterwards.

## Open risks / deviations

- The 4a ACL risk is only partly closed: a launch request that creates the `muxFinder`
  directory first leaves its inherited ACL until the next host-list save. In the app a host
  cannot be attached before a save enabled it; the probe's `attach`/`e2e-*` are the exception.
- Loading only reports a bad directory ACL or mode; it never fixes it (loading writes nothing).
- A save refuses a `hosts.json` that is a symlink, not a regular file, or over 16 MiB; the
  user must move it away. A link or directory that takes the name *during* a save is moved to
  the backup name as it is.
- A store that has neither loaded nor written the file keeps a backup of any file it displaces,
  even a valid one.
- A file system without `RENAME_SWAP` makes every save over an existing file fail with nothing
  replaced (no fallback); `~/Library/Application Support` is APFS on these Macs.
- `--config` must be in a directory the user owns that is not a symlink (`/tmp/x.json` is
  refused because `/tmp` is a link).
- `~user/` include paths are not followed.
