The calls for I-12c1 are in `PLAN.md` ("Calls for I-12c1"): one backend per loaded definition;
attach in D15's order with the backend's own in-memory record as the existing-attachment check;
a plain request with `terminal` and `keepsMinimumLifetime`; confirmation only from evidence
(locally the report's terminal path and attach child pid as the one client's `client_tty` and
`client_pid`, that child alive with the report's kernel start time; remotely the token at the
end of the parent shell's arguments; none = not yet, two = never; no terminal path never
confirms); a helper result before confirmation fails the attach; one focus after confirmation;
no window ever closed by the backend; detach, move here and detach others only through D38's
bound tmux commands; result types extended additively; an end-to-end test of the built helper
on a pty against a private tmux server.

## The workers' calls (recorded in D38 "Plain backend (I-12c1)")

- `PlainTerminalWindowLayer` protocol, which `PlainTerminalWindows` conforms to unchanged, so
  tests drive every open failure and the end to end's fake open starts the real helper.
- New enum cases rather than optional fields: `AttachState` `plainLaunched`,
  `plainStillWaiting`, `plainConfirmed`, `plainFocused`; `AttachFailure` `terminalWindow`,
  `cannotConfirmHere`, `clientCheckFailed`, `alreadyOpenInTerminal`; detach-others problems
  `plainClientListing`, `plainDetach`; optional result fields for the window, client record
  and focus outcome. `isConfirmed` / `isFocused` / `isAttached` hold for the plain states.
  Three UI switches (`SessionActivity`, `AppModelSessions`, `SessionProblem`) got the minimum.
- Factored out of `AttachCoordinator` into `AttachSharedSteps` (behaviour unchanged):
  revalidation, current session by name, session creation. `PlainClientDetach.condition(of:in:)`
  split out of the detach command (text identical) for a read-only presence check.
- Stricter than the coordinator: an attach also waits out an earlier plain attach of the key
  (no attachment index to find what a late helper attached), refusing with
  `earlierLaunchPending`.
- Readings wait for the early report, remotely too (no ssh spent before the helper started).

## Review

Codex (`autoclaude-review.sh`, 20 min) → `ship-with-fixes`, 1 blocker + 2 should-fix —
`docs/reviews/phase-I-12c1.md`. All fixed by a review-fix worker, each regression failing with
its fix reverted:

- **Blocker — detach others not bound to the kept client.** Each per-client detach's
  `if-shell -F` condition now also requires the kept client (name, pid, creation time) in the
  session, composed from the existing condition builders; the loop stops with `identityChanged`
  if the record is dropped or replaced or the kept helper ended; after a refused detach a
  read-only presence check tells "target already gone" (go on) from "kept client gone or
  elsewhere" (record dropped, `identityChanged`). Five tests failed with the fix reverted, one
  on a private tmux server (kept client switched sessions, then ended).
- **Should-fix — helper ending during a confirming reading.** The helper result is checked
  again after the reading and before confirming; `helperEndingDuringAConfirmingReadingFails`
  (local and ssh) failed with the fix reverted.
- **Should-fix — report swept during the remote wait** (sweep at 120 s, remote wait up to
  300 s). The first validated report is kept for the run; a later file that differs ends the
  attach `launchStore(fileMalformed)`. `removedReportStillConfirms` and
  `changedReportIsAFailure` failed with the fix reverted.

## Open risks

- A session whose name contains `{`, `[` or `]` cannot be checked or detached by the bound
  commands; such an attach fails `notWritable` until its helper ends (nothing wrong attached or
  detached). I-12c3 or I-12d decides whether to refuse such sessions up front.
- When detach others stops partway with `identityChanged`, the UI message still says no other
  client was detached, though some may have been (counted in `detachedClients`); noted in
  PLAN.md for I-12d's wording.
- Nothing uses the backend yet; its remote confirmation and the real terminal apps are proven
  only by fakes until I-12c3's `e2e-plain` (Terminal and Ghostty runs under the gate, else
  owed to the user).
- The review-fix worker appended one exit-status echo to a Bash call against the user's shell
  rule (once; harmless).
