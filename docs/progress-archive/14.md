## Review

failed iTerm2 attachment check the refresh engine clears attachments, so the new mapping
showed every live row with clients as "attached elsewhere", even sessions open here. Fixed by
a review-fix worker: the check's outcome reaches the row mapping; only a check that worked
(or found iTerm2 not running) allows "elsewhere"; a failed or not-yet-run check gives the new
"attached, location unknown" state; no row text or accessibility value says "elsewhere".
Regression `attachStateFollowsTheAttachmentCheck` (5 cases) plus `failedAttachmentCheck` and
`fixturesCoverEveryState` fail with the old mapping put back. Report:
`docs/reviews/phase-14.md`.
