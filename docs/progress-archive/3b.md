## What was built

- `Sources/MuxFinderCore/ITerm2/`:
  - `ByteStream` — the byte transport protocol plus the real POSIX `AF_UNIX` stream
    (`poll()`-bounded reads and writes).
  - `WebSocketFrame`, `WebSocketHandshake`, `WebSocketClient` — hand-written RFC 6455 client:
    the *Verified facts* handshake headers, `101` + `Sec-WebSocket-Accept` validation, headers
    split over reads and frame bytes in the header tail, random masking on every client frame,
    7/16/64-bit lengths, continuation reassembly with interleaved control frames, ping→pong,
    close handshake with RFC 6455 §5.5.1/§7.4 close-payload validation, 16 MiB message cap,
    read timeouts.
  - `ITerm2Connection` — actor matching responses to requests by id; one dedicated reader
    thread and one serial writer queue per connection; notifications and unknown ids ignored;
    server `error` submessage surfaced as a typed error; disconnect fails every pending request.
  - `ITerm2CookieProvider` — static `NSAppleScript` source on the main actor, only when iTerm2
    (`com.googlecode.iterm2`) is running; strict `"<cookie> <key>"` parse; -1743 →
    `automationDenied`.
  - `ITerm2Error` — `apiDisabled`, `automationDenied`, `notRunning`, `authRejected` (HTTP 401),
    `protocolError`, timeouts, `disconnected`, and `notSent(reason)` (see *Decisions*).

## Decisions

- **D13 (in `PLAN.md`)**: requests are never retried automatically — a request may have taken
  effect before its connection broke; the next call reconnects with a fresh cookie. After the
  review fix, a request whose frame never started writing fails with `notSent(reason)` (safe
  to retry); one whose frame had started fails with the plain reason (outcome unknown). A
  cancelled request still throws `CancellationError` (outcome not distinguished).
- `authRejected` = HTTP 401 on the handshake and 406 (library too old) → `protocolError`, both
  taken from the Python module's handling; not confirmed live (the run rules forbid sending a
  bogus cookie to the live iTerm2).
- Connection attempts carry a generation number; `disconnect()` fails waiting callers and
  closes a connection that completes late for a stale generation.
- Shutdown after a server-initiated close runs after already-queued frames (a race the
  implementation worker found and fixed).

## Review findings and resolutions

- BLOCKER — cancelled or expired requests stayed queued and could still be sent later: frames
  now carry their deadline and are withdrawable until their write starts; the writer skips
  withdrawn, expired or post-close frames; a started frame is written whole. Tests
  `queuedRequestAbandonedBehindABlockedWriteIsNeverSent` (cancelled and expired),
  `requestAbandonedMidWriteIsStillSentWhole`, `connectionEndWithdrawsQueuedRequests`,
  `writerSkipsWithdrawnAndExpiredMessages`, `unsentDataBeforeACloseIsSkipped`.
- SHOULD-FIX — `disconnect()` ignored an in-flight connection attempt: generation numbers (see
  above). Tests `disconnectDuringCookieRequest`, `disconnectDuringHandshake`,
  `cancelledCallerLeavesTheAttempt`.
- SHOULD-FIX — malformed close payloads accepted and forbidden codes echoed: one-byte payloads
  and non-wire codes → close 1002, invalid UTF-8 reason → 1007, both `protocolError`; valid
  closes echoed. Tests `malformedCloseIsAProtocolViolation` (13 cases), `validCloseIsEchoed`,
  `malformedServerClose`, `wireCloseCodes`, `utf8Validation`.
- Extra in the fix: `ITerm2Connection.close()` no longer busy-spins when its task is cancelled;
  an internal `queuedRequestCount` lets tests observe queueing without timing.

## Open risks carried forward

- `authRejected` (401) and `notRunning` are covered only by hermetic tests.
- What a real tmux tab carries in `ListSessions` (`tmux_window_id`, connection id) is unverified
  until Phase 4; ordinary tabs carry `tmux_window_id = "-1"` and no connection id.

  thread waits on `NSAppleScript`; the app phases must account for that.
