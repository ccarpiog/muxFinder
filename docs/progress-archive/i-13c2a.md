## Review and fixes

Codex (`autoclaude-review.sh`, 20 min budget) → `ship-with-fixes`, 2 blockers + 2 should-fix,
`docs/reviews/phase-I-13c2a.md`. All four fixed by the review-fix worker:

1. **Blocker, quit timeout abandoned the installer** (`ends()`'s result ignored, shutdown went
   on after 10 s). Fixed: `UpdateInstallFailure.cancelled`; the swap checks cancellation at
   its start and right before the exchange (`UpdateSwap.swift`); `stop()` cancels the install
   and waits for it with no deadline; `AppDelegate`'s 15 s termination deadline also waits for
   `UpdateFlow.installEnded()`; `installQuitBound` removed. Regressions
   `aCancelBeforeTheExchangeChangesNothing`, `quitWhileInstallingLetsTheStepEnd` failed with
   the fix reverted; `quitBeforeTheSwapStopsTheInstall` hung on the old code (changed to
   release its held install; not re-run against the old code).
2. **Blocker, edits made during installation were discarded.** Fixed: `UpdateFlow.locksEditing`
   (`AppModel.isInstallingUpdate`) on at install, off when it fails; the New session draft's
   observer reverts changes, `openNewSession` is refused, Settings' `isEditable` and
   `areDirectoriesEditable` read false (their views already follow them), the New session form
   gets `.disabled`. Regression `editsAreRefusedWhileInstalling` passes; **not run against the
   old code** (time).
3. **Should-fix, a cleared notice could not restore the same version's action.** Fixed:
   eligibility cached per version apart from the displayed release. Regression
   `theSameVersionAfterAClearedNoticeRestoresTheOffer` failed with the fix reverted.
4. **Should-fix, notice changes during prepare were dropped.** Fixed: the latest notice kept
   while busy and shown after a cancel or failure; `preparedRelease` is what Install and
   relaunch installs. Regression `aNoticeDuringPrepareIsReconciled` passes; **not run against
   the old code** (time).

## Open risks

- Regressions for findings 2 and 4 unconfirmed against the old code.
- A quit during the install's pre-swap code check now waits for that check to end (the
  15 s termination deadline no longer caps it); the check is local (Security.framework), so it
  is short in practice, but it is unbounded by design of the call.
- Saving in Settings is also refused while an update installs (it goes through
  `isEditable`).
- No real update ran (I-13c3's checklist); no normal launch, no `open`, no request, no real
  swap.
