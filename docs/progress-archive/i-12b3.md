## What was built

- `TerminalBackend` (`Terminals/TerminalBackend.swift`): the seam at the coordinator's session
  operations (attach, move here, create and attach, current session by name, detach a session
  on a host, detach other clients, per-key state) with their present signatures and result
  types, plus `terminal: LaunchTerminalApp` and `focus(_:)` over `TerminalAttachmentHandle`
  (an iTerm2 launch tab session id, or a plain window). No "open here" operation (I-12c,
  requirement 7).
- `ITerm2TerminalBackend`: wraps `AttachCoordinator` (not a conformance, so the coordinator's
  file is untouched); each operation forwards unchanged; a plain handle is refused with nothing
  sent. Tests run the coordinator over its existing fakes and compare results and the requests
  reaching the fakes (the attachment index's identity checks compared in any order, the
  `detach-client` commands in order).
- `PlainTerminalWindows` (main actor) with `PlainTerminalWindowError` (18 typed failures, each
  with a plain sentence) and the seams in `PlainTerminalSeams.swift` / fakes in
  `PlainTerminalFakes.swift`: the facts gate first, then the launch command (mode word from the
  I-12b2 constant), then the script compiled once per loaded definition and `muxfinder_open`;
  `exec` spawned with `posix_spawn` in its own session, standard input and output on
  `/dev/null`, returning at once and never signalling the program, reaped in the background;
  focus by `tty`, `windowID` (`muxfinder_focus`) or `app` (`NSRunningApplication`, never
  launching); close only by a window id this layer's open recorded (`muxfinder_close`; 1001
  `windowBusy`, -1728 `windowGone`).

## Decisions (the workers')

- `ITerm2TerminalBackend` wraps the coordinator rather than conforming it.
- An unrecognised Automation permission status lets an open go ahead (only `denied` stops it,
  with `notDetermined` and `targetNotRunning` going ahead as the calls say); -1743 from any
  handler maps to `permissionDenied`; focus and close refuse an app that is not running.
- No fake `TerminalBackend` yet (I-12c adds one if its UI tests need it).
- Review fixes: every window and close record holds the loaded definition that opened it
  (`openedBy`, compared whole; a focus or close through another definition with the same id
  is `definitionChanged`, nothing read, compiled or sent; reloading the same files gives an
  equal value). A focus answered -1728 forgets that window; an app seen not running (any facts
  read, an open's included, or the activator's `notRunning`) forgets every record of its
  bundle identifier. The reaper keeps a child pending while `waitpid` answers 0 and retries
  after 1, 2, 4 … ms (at most 1 s apart) until the pid or `ECHILD`, chosen over a blocking
  thread per child so no thread is held for a terminal program's lifetime; the wait function
  is injectable for the test.

## Open risks / deviations

- Nothing in the app uses the seam yet; I-12c rewires the app, self-tests and probe onto it.
- An app-facts read that wrongly reports a running app as stopped (right after a launch) would
  make muxFinder forget, so leave open, that window: never a wrong close.
- The unrecognised-permission-status call (open goes ahead) is for I-12c/I-12d to keep or
  revisit with the real runs.
- The review fix edited this phase's own new tests for the window's new shape (5 window values
  and 1 check in `PlainTerminalWindowsTests`, 2 window values in `ITerm2TerminalBackendTests`,
  the failure-sentence table 17 → 18 rows); no pre-existing test changed.
- One full `swift test` run of the implementation worker failed
  `FolderSearchTransportTests.answersAndEndsAtEndOfInput` (a 2 s timing bound, untouched
  code, load-sensitive as recorded since I-12a); it passed alone and in every later run.
