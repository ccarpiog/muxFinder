## Decisions (the worker's, recorded in D39)

- A constant `Accept-Language: en` header is sent, so macOS adds none from the user's
  language settings (not identifying; the stub could not otherwise see what the system adds).
- The probe's logic lives in the core (`UpdateProbe`) so it is tested over a fake transport;
  `UpdateCommand.swift` only plugs in the real transport. Usage errors exit 64.
- An unreadable answer (not JSON, wrong shape, over 1 MiB) is a failed check, retried after an
  hour; a draft, prerelease, unknown tag or foreign release page is a successful check that
  offers nothing.
- A rate limit's reset is recorded at most 24 h ahead; a stored date further ahead is ignored
  (the clock went back).
- No lock on `update-state.json` (a cache: last write wins, an invalid file replaced without a
  backup).
- The worker found and fixed its own bug: a clock set back between start and the first check
  lost that check; a regression covers it.
- Not wired yet (I-13c): nothing writes the "notice seen" version, nothing in the app creates
  the scheduler or reads the toggle.

## Review

Codex (`autoclaude-review.sh`, 15 min) → `ship-with-fixes`, 0 blockers, 2 should-fix —
`docs/reviews/phase-I-13a.md`:

1. `UpdateScheduler.swift`: wake or toggle events during a slow state load could arm an
   automatic check that bypassed the persisted throttling. **Fixed**: nothing is armed or run
   until the state has loaded; events during the load are folded into the evaluation after it;
   a manual check waits for the load, so a saved rate limit holds it. Regressions
   `wakeDuringASuspendedLoadWaitsForTheState` and
   `toggleAndManualCheckDuringASuspendedLoadKeepTheRateLimit` (fake `SuspendedUpdateStateStore`)
   failed on the old code (8 and 10 issues).
2. `UpdateProbe.swift`: `--state` accepted shared folders or folders with ACLs, which the
   store then chmodded. **Fixed**: the probe refuses (exit 64, before any transport) a folder
   that is not already private (no group/other permission, no ACL); the store's new
   `existingPrivate` policy refuses rather than tightens (`directoryNotPrivate`); the app's
   default policy and the shared helper are unchanged. Regressions
   `nonPrivateStateFolderIsRefusedAndLeftAsItIs` (modes 755/750/705/770/701 and a real ACL
   entry) and `existingPrivatePolicyChangesNoFolder` failed on the old code (48 and 3 issues).
